# Shared semantic index

The daemon maintains one logical index per checkout. Duplication, architecture, test-impact and verification checkers query the same revisioned workspace facts. A checker that needs a new kind of fact requests it through the scheduler. It reuses the same project context, symbol identities and scheduler budget as other consumers. Compilations supply symbol facts for these queries. MSBuild owns compiler diagnostics.

## Indexed facts

| Fact | Identity and retained evidence |
| --- | --- |
| Workspace and build graph | Canonical path, content digest, evaluated compile membership, project references, imports, defines, toolchain, target framework, configuration and generator inputs. Treat linked files and multi-target compilations as distinct document contexts when they bind differently. |
| Declaration and reference | Opaque symbol ID scoped to its evaluated build context, declaration spans and typed references. Distinguish invocation, construction, read, write, type use, attribute and registration. Use compiler symbol equality within a compilation and derive durable IDs from declaration identity, containing assembly and context. Give locals and anonymous constructs document-local anchors. |
| Calls and dispatch | Caller, callee, call site, receiver, and direct, possible or unresolved binding. Keep reverse edges for incoming calls and forward edges for outgoing calls. Index explicit and implicit interface implementations, base/override relationships, and alternate dispatch targets. Retain supported delegate bindings, event registrations and DI bindings with the reason they were inferred. |
| Value flow | Store compact summaries from parameters, constants, configuration, fields and calls through assignments and conversions to returns, arguments, writes, exceptions and effects. Include `ref` and `out` flows where resolved. Tag recognized boundaries, such as HTTP input, serializers, persistence, queues, log fields and public responses. |
| Test and operational evidence | Stable adapter-scoped test IDs, test entry points, reachable symbols, assertions where recognized, receipts, coverage hits, and evidence from repository artifacts or optional imports. Distinguish a static test-to-symbol connection from a measured execution hit. |
| Source facts | Token fingerprints for duplication, file-kind and generated-code flags, source spans, rule versions and input digests. Keep checker-specific payloads under the same revision, invalidation and storage rules. |

Collect references and implementations with Roslyn semantic APIs, and use `IOperation` and `ControlFlowGraph` to extract bound calls and intra-procedural value origins and destinations. Propagate bounded summaries across calls for arguments, returns and effects. Stop at an external boundary unless an adapter supplies a documented model. Runtime reflection, dynamic dispatch, unresolved aliases, native calls and unavailable generator results limit coverage. Record the frontier and the reason rather than treating missing edges as proof that a path is absent. [Roslyn references](https://learn.microsoft.com/en-us/dotnet/api/microsoft.codeanalysis.findsymbols.symbolfinder.findreferencesasync?view=roslyn-dotnet-5.0.0), [Roslyn implementations](https://learn.microsoft.com/en-us/dotnet/api/microsoft.codeanalysis.findsymbols.symbolfinder.findimplementationsasync?view=roslyn-dotnet-5.0.0), [Roslyn operations](https://learn.microsoft.com/en-us/dotnet/api/microsoft.codeanalysis.ioperation?view=roslyn-dotnet-5.3.0), [Roslyn control-flow graphs](https://learn.microsoft.com/en-us/dotnet/api/microsoft.codeanalysis.flowanalysis.controlflowgraph?view=roslyn-dotnet-5.3.0)

## Evaluated input identity

Give each evaluated target a stable context key comprising the workspace-relative project, target framework, configuration, platform, applicable runtime identifier and toolchain. Keep the content fingerprint separate so a new build of the same context supersedes its old facts. Derive the key from evaluated properties. The mapped target of a project reference comes from evaluation. A test targeting a newer framework may reference a library built for a different one.

| Partition | Fingerprint inputs |
| --- | --- |
| Graph and membership | Project and import digests, evaluated properties and reference mappings, SDK selection, relevant environment and the expansion of item globs. Record which directories the globs searched so an addition can invalidate an empty match. |
| Compilation | Graph fingerprint, ordered compiler inputs, logical and physical source paths and digests, reference assembly identities and contents, defines, parse and compilation options, analyzer configuration and additional files. |
| Generated sources | Generator binaries and inputs, ordered output identities and digests, and the compilation context that consumed them. Missing or disabled generators leave the associated semantics partial when required by that context. |
| Test evidence | Compiled test and dependency outputs, target runtime, runner and adapter identity, settings, test assets and declared runtime input fingerprints. Verification strength records whether the inputs were observed in a live checkout or held immutable. |

Compare fingerprints within a versioned domain that includes the canonicalization scheme. Keep semantics-sensitive ordering and distinguish absent from unknown evidence. If imports, generated inputs or references cannot be enumerated completely, retain the affected frontier and avoid claiming a reusable complete result. Keep source inventories shared while indexing a linked file separately in every context that binds it. A current target query returns the current facts and coverage frontier or identifies the missing partition.

## Change queries

1. Map each changed span to the smallest old and new semantic owners. Include callers when a signature, visibility, attribute, default value, contract or dispatch registration changes. Compare old and new edges for a changed overload, deleted method or removed implementation. Mark ambiguous mappings explicitly and broaden impact to the owning context.
2. Traverse incoming edges toward entry points and tests, and outgoing edges toward dependencies and effects. Return candidate call chains with source sites and dispatch evidence. Call chains reflect static analysis. Imported runtime stacks or traces carry their own provenance.
3. Trace value origins backward and destinations forward from modified expressions and symbols. Report relevant flows through test assertions and external boundaries. Record certainty per edge and truncate on a node, depth or time budget, using cycle detection and stable ordering.
4. Return the workspace revision, build context, relevant spans and a coverage frontier. Differentiate an exact binding, a candidate, an unresolved edge and an index partition that has yet to be built. Source inventory and pending intent status remain available while semantic partitions are cold.

Partition declaration and direct-edge facts by document and context. Start by rebinding the affected target and dependent targets whenever their compilation dependencies change or are unknown. Narrow body-only invalidation only after cold and warm results agree for edits that change inferred types, partial declarations, generated content or summaries. Traverse recursive calls with a visited set and report a bounded frontier. Expand possible dispatch targets without turning candidate edges into exact calls. A deletion invalidates old edges, linked findings and impacted tests in the same transaction. Keep a bounded predecessor view for delta analysis so a removed symbol can still be traced to its former callers and tests. Publish indexed facts, completeness and the invalidation list together. Recheck relevant input digests before publishing.

## Disk cache and memory budget

Use one local SQLite database for compact facts, indexes and revision metadata. Store bidirectional adjacency as indexed edges, intern repeated identifiers and store line or offset ranges instead of syntax trees or source bodies. Use a single writer with short transactions and bounded read snapshots. Manage write-ahead log checkpoints and cap retained generations, cursor age, disk use and large external artifacts. Prototype with a 256 MiB per-checkout disk allowance for the database and journal combined, plus a per-user quota across checkouts. Reserve headroom for updates and checkpoints. A reader that outlives retention gets an expired revision and can acquire a new snapshot. Discard incompatible partitions on schema, adapter or compiler changes. Resume valid partitions on restart and rebuild missing work in priority order. [SQLite write-ahead logging](https://www.sqlite.org/wal.html)

Start with a configurable 32 MiB in-process index budget per active checkout, charging SQLite pages, decoded graph pages, buffered records and cached summaries against it. Keep a separate configurable aggregate memory allowance for Roslyn and external worker process trees, with memory measured outside the index budget. Use weighted eviction for decoded graph pages and source summaries. Keep compilations and semantic models in recyclable workers. Write facts in bounded chunks and prioritize the active dirty scope before indexing the rest of the checkout in idle slices. Under pressure, evict cached pages, shorten retention and defer cold analysis. Surface the affected scopes and reasons. A deferred or evicted partition can be rebuilt when requested. Use the same index-backed query path for automated checks and MCP requests so they see consistent edges and reuse work.
