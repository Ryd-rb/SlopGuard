# Production-inspired Luna Low trial

Use current SlopHawk main `0547270` and one fixed set of three newly packed .NET projects. All six benchmark workers use `gpt-6-luna` at `low` effort in separate fresh turns. These are local reproductions of failure patterns. Public issue reports, vendor names, hidden inputs and corrected source stay outside worker dossiers.

## Sources and counterfactuals

Defects4J separates deterministic fault-triggering tests from broader regression checks. The trial adopts that evidence structure. It also uses the derived-query pattern from SWE-bench instance `django__django-10554`. Every project has a passing ordinary test and two valid public examples, plus a hidden workload that distinguishes the buggy and corrected implementations. [Defects4J](https://github.com/rjust/defects4j) · [SWE-bench](https://www.swebench.com/original) · [SWE-prime case index](https://huggingface.co/datasets/SWE-bench/SWE-prime)

The author runs three native VSTest smoke checks linked against the shipped application source. The inspector must independently replay every archived run as passed. The author runs the original and separately corrected executables on both public profiles and the hidden trigger. Original and repaired results must agree for both public profiles. On the trigger, only the corrected version meets the contract. The preflight uses real output bytes and deterministic schedules with no sleeps or external services. A passing smoke receipt is legitimate evidence for the tested slice and supplies no verdict about the hidden workload. The treatment measures how useful that limited evidence is to a reviewer doing a behavioral audit. It is deliberately harder than looking up a negative tool verdict.

## Assignment and measurements

Freeze all three project trees and the inspector before dispatch. Draw uniformly among the six three-pair order assignments that include at least one assisted-first and one ordinary-first pair. Use the same worker brief and four-minute instruction in both arms. Tool-call counts are uncapped. Only the assisted brief supplies `Inspector ROOT archive release/next.json`. Both arms may create executable counterexamples in their private scratch and run the documented local tools. Treat worker outputs as untrusted until checked against the oracle. No networks, author paths, other reviewers or edits to the dossier. Verify all paths and per-entry fingerprints after the runs.

Score once per seeded cause with the above reproduction bar. Honest evidence gaps do not count as false positives. A claim is a false positive when it asserts a blocker that the policy or runnable counterexample disproves, including objections to the supplied valid profiles. Both subjects are blind to the key and peer results. The coordinator scores with access to the arm labels. Keep every launched run and read the final cumulative token event for actual model, effort, input, cached input, output and reasoning. Report calls, time, missing telemetry and any invalid assignments. The three paired differences are descriptive.
