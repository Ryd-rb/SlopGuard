# Benchmark design for the C# path and intent checker

This is a proposed test protocol for the [checker](../../docs/path-intent-checker.md). The main question is whether adding path exploration to current SlopHawk gives a fresh reviewer more reproducible, contract-grounded defects with the same information. The experiment also measures where extra prompts, confusing reports, or incorrect rules introduce false positives or extra cost.

## Proving the checker works

Test the mechanics through the public CLI and the declared adapter before running any agent pair. These small cases are development tests. Use different source and defect variants for the blinded holdout. The scalar gate uses the existing numeric adapter and compatible exact comparisons. The stateful holdout also requires the typed adapter checks below.

| Test | Required evidence |
|---|---|
| Build context and bound body | Vary target defines, generated source and an overload. A missing or stale compiler manifest leaves a scoped structural result. A declaration hint resolves to one bound body for the selected target. |
| Branch polarity and short circuit | Match the Roslyn edges to execution for nested Boolean conditions and a short-circuited divide. Record a trace only where the adapter proves the edge. |
| Reachability on small finite methods | Independently enumerate a small C# input and fixture domain including overlapping and contradictory guards. Match supported predictions and every in-domain infeasibility claim to compiled ground truth. One model mismatch invalidates claims from the affected translation. |
| Numeric semantics | Cover signed extremes and unchecked wrapping. Check that promotions, narrowing, remainder, and checked overflow remain unknown until qualified. Before widening, verify each operation family against compiled values, control flow and exceptional exits, with short-circuit and signed-boundary cases. |
| Public setup | Verify a reachable pre-state via the public fixture. A requested state the setup cannot establish is a setup failure. |
| Returns, state and effects | Use a correct return value with an incorrect state, a correct state with an extra effect, and an intentional exception with the expected preserved state. Test missing fields separately from explicit nulls. |
| Allowed outcomes | Verify two allowed outcomes each pass. A hybrid combining the return value from one outcome with the state from the other fails. |
| State isolation and sequence | Fresh equivalent fixtures reproduce, including declared state outside the fixture. Poison a shared effect store and verify reset or surface the failure. Check that a saved before snapshot survives mutation and that two calls share only their intended state. |
| Response attribution | Swap same-length batch payloads, duplicate a reply ID, reuse a case ID with a different recipe, and fail during the first reviewed operation. Reject mismatched payloads and distinguish setup, invocation and recorder failures. |
| Trace attribution | Collapse two invocations into aggregate coverage and attempt to attribute a hit to either invocation. Keep that attribution unknown. Require a verified map for a trace from an instrumented build and replay the behavior on the original build. |
| Expectation provenance | Replay a wrong rule that passed its examples. Exercise a valid return citation with an unsupported effect assertion, a stale policy, an outcome-dependent antecedent and conflicting authorities. Test that a new observation-informed rule retains that provenance. |
| Unknowns and budgets | Exercise an opaque call, a loop beyond the search limit, an unsupported value type, solver unknown, and adapter timeout. Each records an unresolved frontier and yields no definitive finding for that frontier. |
| Evidence identity | Change the build, dependencies, fixture or target after planning and reject stale execution evidence. Re-evaluate a compatible receipt under a new intent revision and retain both evaluations. Compare normalized plans and observations across equivalent runs. |
| Review integration | Interrupt publication at each artifact and substitute a same-length receipt. A reader rejects incomplete or mismatched seals and identifies superseded runs. Publish again from writable scratch while the source daemon continues exporting successfully. |

Use exhaustive and differential checks during development where the domain is small enough. Test implementations with different branch spelling and method names to catch dependence on surface syntax. Exercise structural analysis without an execution adapter and runtime comparison without a trace. The output should distinguish those capabilities.

### Concrete development defect

Use a pickup coordinator with a fast path that stages a last-copy allocation for reserved pickup. Both the normal path and the fast path recognize a closed pickup branch. When policy denies fallback, the fast path in the mutant returns the correct `BranchClosed` value without rolling back the staged decrement.

| Input or control | Expected observation |
|---|---|
| One free copy, reserved pickup, closed branch, fallback denied | Return `BranchClosed`, retain the free copy and pending hold, emit no allocation. |
| Two free copies, same request and branch policy | Return `BranchClosed`, retain both free copies and the pending hold, emit no allocation. |
| One free copy, reserved pickup, branch open, fallback denied | Return an assignment, consume one copy, mark the hold assigned, emit one allocation. |
| Same first case against the corrected version | Match the expected return, state, and effects. |

The mutant should exhibit a difference only in available stock on the first input. Require a saved replayable setup, exact state observation, and a sourced expectation before blaming the rollback. Use the branch identities to test that conjunctive search reaches the fast-path rejection. Keep this example and its near neighbors out of scored recognition tests. An independently authored holdout can use a different late rejection and state projection.

### Scalar gate

Have an independent author freeze a small return-only workload using supported `int` and `bool` paths, public integer rules, and the existing numeric adapter. Include ordinary examples, clean controls, and private witnesses for admitted rule violations that the ordinary examples pass. Keep combined conditions in current SlopHawk’s baseline. Compare the same targets under the engine ablation in Experiment A. Require one independently verified, saved graph-generated return violation missed by graph-off within the planned execution and resource limits. A valid no-gain result stops expansion from this pilot. Missing compiler identity, unresolved policy, or a broken adapter makes the comparison inconclusive. Record setup effort, checker time, and any false positives before funding the typed adapter and stateful holdout.

## Fresh holdout

Use a C# library consortium circulation system. It has several branches, pickup holds, patron eligibility, copy assignment, renewals, a charge ledger, and recorded notification events. It exposes normal methods that return decisions and update an in-memory fixture. All time and dependency outcomes come from declared fixture inputs. The public adapter can set up a reachable state, invoke the same production code in every arm, and return a structured observation. Every worker has the same access to observations and the same public policy. The author keeps a separately implemented reference and private witnesses.

Aim for three genuinely different variants per family, up to 48 qualified variants. Draw one per qualified family and include eight correct controls. The table is a public authoring brief. Keep the actual guards, state transitions, method names, witnesses, and selection private. Use fresh mechanisms or combinations where a public example gives away how to find a fault. Families 1–12 are the primary comparison. The last four probe the limits of the initial model and are reported separately. Freeze any shortfall in qualified families before allocation and publish the actual denominators.

| Family | Proposed three variations |
|---|---|
| 1. Late transit receipt reopens a retired hold | Reopen a withdrawn hold, extend an expired hold’s pickup deadline, or emit pickup-ready for a completed hold when a late transit receipt is accepted. Keep receipt logging correct while checking the retired hold and effects. |
| 2. Repeated scan repeats a side effect | A second scan with the same receipt creates another loan row, adds another fee, or emits another event while returning the cached success decision. |
| 3. Equal timestamps reorder holds | Two holds share the same readiness time. Break the tie by the wrong original receipt, by the normalized branch alias, or before filtering an ineligible hold. Inspect the stored queue. |
| 4. Valid renewal updates the wrong field | Return the new due date while changing a sibling loan, retaining the outdated stored due date, or leaving a conflicting renewal event. Use a valid case with both a current and a historical loan record. |
| 5. Waiver applies to the wrong revision | Use stale, future or adjacent-version authorizations on renewal, under a path combining current eligibility, renewal count, and grandfathered status. A near neighbor is eligible under the same policy. |
| 6. Optional pickup defaults fail | On different routes, a missing pickup preference, unavailable preferred slot, or absent override record should use a documented fallback. Seed an exception or incorrect default on only one admitted late branch per variant. |
| 7. Returning a copy loses a hold transition | Return to this branch while a transferable hold exists. Seed a missed transfer status, a stale reservation owner, or a wrong effect payload on the equal-priority or last-copy branch. |
| 8. Replacement quote mutates the ledger | A quote with a partial credit can incorrectly post a debit, reserve the credit, or advance the ledger version even though the result amount is right. |
| 9. Returning a different copy closes the wrong loan | Combine an item identifier collision, a copy-level match, and distinct patron or branch records. Variants select by catalog ID, stale copy alias, or the first matching owner. |
| 10. Notification allowed only after eligibility | Mutate the event when opt-out and a deadline coincide, dispatch to the old patron after an allowed transfer, or issue a second notification after a suppressed retry. Judge the recorded effects and metadata. |
| 11. Inventory transfer double-applies a boundary delta | On the last free copy, decrement the sending count twice, increment the destination on a rejected alternate route, or let a zero-item transfer consume the pending quota. Include valid adjacent cases. |
| 12. Staged adjustment uses the wrong snapshot | Make two allowed calls. In different variants use the pre-return count, the newly staged count before commit, or the canceled snapshot during final availability calculation. Score the resulting count and assignment. |
| 13. Exception cleanup drops state | Seed a failure in a declared dependency scenario and exercise catch, finally, or deferred cleanup variants. Record the rollback or allowed partial outcome without assuming complete static exception modeling. |
| 14. Bounded queue loop misses a candidate | Vary where a skip, stop, or duplicate row causes the first or second iteration to miss a later eligible hold. Record when the loop exceeds the supported bound. |
| 15. Distinct objects share a mutable record | Use reachable aliasing through a stored reference, a shallow copy, or shared collection membership. Observe the unexpected change in the untouched view. Score the behavior separately from static alias reasoning. |
| 16. External condition changes the valid state transition | Through a declared test double, vary a failed lookup, stale dependency revision, or deferred response. Each changes the permitted result. No private dependency outcomes are supplied as path witnesses to the worker. |

Correct controls cover a deliberate exception with preserved state, an allowed alternative result, a correct zero-delta transition, a correct rejected-call rollback, a legitimate repeated-call replay, a guard with a contradictory path, an opaque helper, and an explicit effect whose ordering is outside the contract. Publish these operations alongside the defect families without control labels. Add admitted near neighbors for each private witness so the scorer can distinguish a real violation from an input that merely entered a rare branch.

Preclassify the variants by mechanism before seeing detection results. Include rare guard conjunctions, branch-neutral differences within the same path, and cases mainly limited by state or fixture construction. A correct receipt can leave the wrong sibling loan updated on a path both modes reach. An oracle must distinguish the sibling states and the search must choose unequal values for that case to expose the error. Expose the same neutral legal setup recipes to both modes.

Freeze the public policies, admission rules and legal fixture routes before seeding variants. Before allocation, the author compiles clean and mutated code under the same target and flags. Each variant must pass ordinary examples and have a publicly reconstructible setup, realized in-contract pre-state, a stable private witness observed at a complete boundary, and admitted near neighbors. Independently qualify the policy and the corrected reference on these cases. Record mechanism clusters so cosmetic variants do not inflate independent support. Keep the full qualification ledger, including unreachable, ambiguous, equivalent, unstable, redundant and trivial cases, with reasons. Freeze the eligible variants and exclusions without consulting either checker’s detection scores.

Freeze the author package, candidate builds, public contracts, executable expectations, fixture adapter, corrected reference, manifests, model, and tool versions before launching workers. Use a recorded seed to select one approved variant per family and share that exact draw within a pair. Give each worker a single candidate snapshot with neutral fixture names and an allowlist of public files. Keep source history, the generator, seed, defect count, witnesses, reference, scoring, and experiment design outside both workspaces. Preflight forbidden reads from the worker identity and hash the shared files. Produce worker-visible plans, traces, cards and summaries solely from the candidate and allowlisted public inputs. Scan them for known private identifiers, witness leakage, and authoring fingerprints without exposing the scan output to workers. Record a failed preflight as a protocol failure. Before claiming generality, repeat in a disjoint domain with a fresh author and use an operation/name permutation on a matched draw to check sensitivity to surface names.

## Experiment A · Does path exploration add value?

First compare deterministic graph-off and graph-on search. Hold method targets, legal setup recipes, intent, observation comparator and summary format fixed. Freeze the ordinary and current probe streams, including implementation literals, joint conditions, correlated argument changes and any shared generic fixture or sequence probes. Give both modes the same maximum distinct admitted cases and confirmation reserve. Record ordered candidate origins, duplicates, rejected setups, actual executions including retries and confirmations, solver work, CPU time and elapsed time. Report first verified witness and cumulative yield by both distinct cases and a predeclared compute or wall-time budget. Separate a newly generated graph witness from a shared witness scheduled earlier. Report graph-off-only findings too.

Then run a matched pair of fresh Luna 6 Low sessions in separate read-only workspaces with writable scratch. Use one turn, uncapped agent tool calls, and identical public files, adapter, executable intent, examples, and short prompt. Randomize the first order and reverse it for the second pair on each confirmation draw. Both receive current SlopHawk. The treatment adds the path explorer and its generic workflow. This pair estimates the benefit of making that workflow available. Publish no precomputed distinguishing inputs. Freeze a common end-to-end deadline, model snapshot and permissions, and record enabled tools and command and analyzer limits before launch. Record deadline truncation as an outcome. An ordinary-tools arm can separately measure the full workflow against no SlopHawk.

> Review the solution listed in workspace.json. Flag reproducible behavioral defects without editing the solution. Run any listed checker. Save out/answer.json with the operation, setup and inputs, actual outcome or state, expected outcome or state, the public rule supporting the expectation, and cause for each finding. Tool calls are uncapped.

Give both arms the same state projection, intent evaluator, and batch runner. Use the current checker for exact JSON comparisons and a shared fixture comparator for any additional predicates required by the test. A worker may derive new expectations, inspect the same code and policy, and run the adapter directly. Only the treatment receives graph-directed case generation and its review output. A comparison against the unmodified shipped workflow can also measure the combined improvement from the comparator and path explorer. Report that comparison as a workflow result. Count what each worker submits and retain tool receipts. Score the checker’s own witnesses separately to distinguish discovery from an agent’s decision to report.

Start with one draw, the deterministic comparison, and at most one reviewer pair. Estimate and reserve the total run budget before launching. A worker that ends early or returns a partial audit is an observed outcome. An infrastructure failure before a usable turn may be retried on the same draw with a fresh session and stays in the record. Freeze any revised protocol before new confirmation draws, retain the pilot, and distinguish workflow gain, no gain, and an inconclusive protocol failure.

For confirmation, plan four new draws with two matched pairs per draw. Report each pair’s per-arm counts and net gain, average the two gains for each draw, and weight the draws equally. Repeated sessions on one draw measure reviewer variability. Preselect any exact variant for additional consistency repetitions. Family rates pool variants and should report their composition. A descriptive target is baseline verification in at most half the matched repetitions and treatment verification in at least three quarters.

A proposed descriptive product gate is a mean of at least three additional verified primary defects per pair, a positive aggregate gain on at least three of four confirmation draws, and no increase in aggregate false-positive count. Four draws are a small sample, and several defects found in one session share context. Publish the raw pairs, draw-level variability, and submission error rates. Broader claims need more domains and an inference plan set before collecting those data.

## Experiment B · Do intent questions help?

Keep the path engine and generated goals fixed. Give both candidate-blind expectation authors the same neutral setup card, policy revision, observable fields, time allowance, and opportunity to write an answer. Randomize free-form versus structured prompts across comparable cards and authors. Freeze the exact prompt, approved clauses, authority judgments, exposure record and answers before candidate replay. Grade source-only cards separately from any candidate-conditioned cards. A comparison that adds the opportunity to author a rule measures the whole authoring workflow. A reviewing agent who already saw the implementation belongs in a separate measurement.

Start with six to eight prewritten cards where policy is clear, legitimately ambiguous, permits multiple outcomes, or conflicts with a stale example. Grade against an independently authored rubric before paying for additional reviewer pairs. Measure grounded rules, correct unresolved decisions, wrong or overconstrained expectations, and verified defects when paired with replay. Count authoring tokens, waiting time, reviewer tokens, and replay cost. An effect that requires private ground truth to answer stays unresolved in the worker session.

## Scoring and cost

Remove arm and run hints before adjudication. Independently replay cases on the frozen candidate and corrected reference. Validate the realized setup, admitted input, cited rule and exact claimed failing observation. Apply policy when it permits multiple whole outcomes. Resolve reference and policy disagreements before crediting a finding. Record actual policy violation and submission accuracy separately. Credit at most one verified seeded defect per family per session and score causal or branch attribution separately. A false positive asserts a violation for a case that satisfies independently grounded policy. Classify wrong claimed values on real defects, invalid setups, unresolved or unsupported claims, unstable replay, and genuine new defects separately. Independently confirm new defects and report them outside seeded yield.

Use all submissions for disposition rates and determinate positive claims for exact-confirmation precision. Report seeded yield out of the primary families actually exposed, with separate denominators for limit cases and clean controls. Keep started incomplete sessions in per-session yield and report any pre-turn infrastructure failures and retries explicitly. For the path engine report supported goals, attributed branch hits, replayed cases, unknown goals and stop reasons.

For each run record cached and uncached input, output and total tokens from session telemetry, with reasoning tokens shown only if reported and counted once. Report checker and solver work, CPU or wall time, tool calls, adapter and compilation setup, and any separately incurred intent authoring cost. Include partial and unsuccessful started runs. Label unavailable counters as missing. Report costs and yield side by side when the incremental verified yield is zero or negative.

Before scaling the stateful pilot, require an independently verified return, state, or effect violation reached by a saved graph-goal case that the matched graph-off mode missed within budget. A valid run can show no gain or a loss. Release negative findings and incomplete sessions alongside favorable outcomes.
